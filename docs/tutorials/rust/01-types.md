# 1. Типы, которые предотвращают ошибки

У файлового менеджера много состояний: открыта панель, запрашивается пароль,
выполняется загрузка, показана ошибка. Если каждое состояние обозначить отдельным
флагом, код сможет одновременно объявить загрузку завершённой и продолжающейся.
Компилятор не увидит противоречия: оба флага имеют допустимый тип `bool`.

## Enum хранит только допустимую форму состояния

```rust
enum TransferState {
    Queued,
    Running { copied: Bytes },
    Finished { copied: Bytes },
    Failed(TransferError),
}

#[derive(Clone, Copy)]
struct Bytes(u64);

enum TransferError {
    PermissionDenied,
    ConnectionLost,
}
```

У завершённой передачи есть количество скопированных байтов, а у ошибки — причина.
Состояние `Failed` без ошибки создать нельзя. Для показа результата используйте
исчерпывающий `match`:

```rust
fn label(state: &TransferState) -> &'static str {
    match state {
        TransferState::Queued => "Queued",
        TransferState::Running { .. } => "Running",
        TransferState::Finished { .. } => "Finished",
        TransferState::Failed(_) => "Failed",
    }
}
```

После добавления варианта компилятор укажет места, которые требуют решения.
Общий `_ =>` скроет часть этой помощи. В FFM примером служит
[Overlay](../../../src/models/overlay.rs): один вариант определяет активное окно.

Enum не обязан объединять независимые измерения. Вид панелей и наличие диалога
могут меняться независимо; их разумно хранить раздельно.

## Newtype отделяет смысл от представления

Параметры `from: u64, to: u64` легко перепутать с размерами или идентификаторами.
Обёртка `struct Bytes(u64)` создаёт отдельный тип без отдельного выделения памяти.
В отличие от `type Bytes = u64`, она запрещает неявную подстановку другого числа.

Для ограниченного значения закройте поле и проверяйте его в конструкторе:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct ServerPort(u16);

#[derive(Debug, PartialEq, Eq)]
enum PortError {
    Zero,
}

impl TryFrom<u16> for ServerPort {
    type Error = PortError;

    fn try_from(value: u16) -> Result<Self, Self::Error> {
        if value == 0 {
            return Err(PortError::Zero);
        }
        Ok(Self(value))
    }
}
```

Код внутри домена теперь принимает `ServerPort`, а не повторяет проверку нуля.
В FFM изучите [типы сессии](../../../src/models/session.rs) и
[UnixMode](../../../src/remote/metadata.rs). Проверка нужна и при чтении YAML:
производный `Deserialize` с открытым внутренним полем может обойти конструктор.
Используйте `#[serde(try_from = "String")]` или собственную десериализацию.

## Option и Result выражают разные ситуации

`Option<Session>` означает, что сохранённого подключения может не быть.
`Result<Session, Error>` означает, что операция может завершиться ошибкой.
Отсутствующий профиль и недоступный файл конфигурации требуют разных действий.
Не превращайте оба случая в пустой список через `unwrap_or_default()`.

## Не все derive безопасны

Для обычного идентификатора полезны `Clone`, `Debug`, `Eq` и `Hash`.
Для пароля `Debug` может раскрыть секрет, `Serialize` — записать его на диск,
а лишний `Clone` увеличивает число копий. Выбирайте каждый derive по смыслу.
Секрет и ссылка на переменную окружения с секретом — разные доменные типы.

## Упражнение

Спроектируйте `ConnectionState`: отключено, подключается, подключено, ошибка.
Только подключённое состояние должно хранить транспорт. Отдельно создайте
проверяемый тип имени сервера. Напишите тесты на пустое имя и управляющие символы.

Критерий: получить транспорт из отключённого состояния невозможно без явной
обработки варианта, а недопустимое имя не проходит конструктор.
