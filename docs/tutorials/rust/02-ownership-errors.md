# 2. Владение, заимствования и ошибки

В Rust у значения есть владелец, который отвечает за его освобождение.
Заимствование позволяет использовать значение, не передавая владение.
Начинайте с вопроса: функция только читает данные, изменяет их или забирает?

| Намерение | Тип параметра |
|---|---|
| Прочитать текст | `&str` |
| Прочитать путь | `&Path` |
| Прочитать последовательность | `&[Entry]` |
| Изменить состояние | `&mut Panel` |
| Передать владение рабочему потоку | Собственное значение, например `Request` |

## Заимствуйте на время операции

```rust
use std::path::{Path, PathBuf};

fn child_path(directory: &Path, name: &str) -> PathBuf {
    directory.join(name)
}
```

Функция читает аргументы и возвращает собственный результат.
Она не требует от вызывающего кода создавать `String` или отдавать `PathBuf`.
Для пути из недоверенного источника дополнительно нужен проверяемый тип имени:
`join` сам по себе не является защитой от абсолютного пути или `..`.

Одна изменяемая ссылка даёт исключительный доступ на время заимствования.
Если компилятор отказывает в двух одновременных доступах к `App`, сократите
время заимствования: вычислите нужное значение, завершите работу со ссылкой,
затем выполните следующий переход состояния.

## Clone — осознанная операция

`String::clone()` копирует байты. `Arc::clone()` увеличивает счётчик общей ссылки.
Одинаковое имя метода не означает одинаковую стоимость или независимость данных.
Сначала попробуйте передать ссылку. Копируйте снимок, когда он действительно
должен пережить текущий обработчик, например для фонового запроса.

Не добавляйте `Arc<Mutex<_>>` только ради обхода правил заимствования.
В дереве UI обычно достаточно единственного владельца и `&mut`.
Mutex нужен при реальном совместном доступе потоков. Не держите его во время
ожидания ввода пользователя и учитывайте длительность сетевой операции.

## Ошибка — часть интерфейса

```rust
use std::io;

#[derive(Debug)]
enum LoadError {
    Read(io::Error),
    InvalidFormat,
}

fn read_profile(path: &std::path::Path) -> Result<String, LoadError> {
    let text = std::fs::read_to_string(path).map_err(LoadError::Read)?;
    if text.trim().is_empty() {
        return Err(LoadError::InvalidFormat);
    }
    Ok(text)
}
```

Оператор `?` возвращает ошибку вызывающему коду. `map_err` переводит ошибку
на границу текущего модуля. В рабочем коде добавьте `Display` и
`std::error::Error`, а преобразование `From` используйте, когда оно однозначно.
Не создавайте одно гигантское перечисление ошибок всего приложения.

Тип ошибки помогает решить, что делать: предложить повтор, запросить права,
сообщить об изменении файла. Для решений используйте варианты enum, а не поиск
слов в строке сообщения. Сообщение для пользователя и внутренние подробности
могут отличаться; оба канала должны исключать пароли, ключи и содержимое ответа,
которое провайдер мог включить в ошибку.

## Сохранение не должно уничтожать исходник

Для конфигурации важен весь протокол:

1. Прочитать и проверить существующий документ.
2. Сравнить изменённые значения с загруженной версией.
3. Сохранить разделы, которыми операция не владеет.
4. Записать временный файл с нужными правами.
5. Заменить целевой файл атомарным переименованием, если платформа это допускает.

Атомарная замена защищает от частичной записи, но сама не предотвращает потерю
параллельных изменений. Для этого нужны блокировка и проверка версии.
В FFM разберите [сохранение документа](../../../src/config/document/save.rs).

## Упражнение

Напишите функцию загрузки списка профилей с отдельными ошибками чтения и разбора.
Отсутствующий файл считайте первым запуском, а повреждённый файл оставляйте
нетронутым. Добавьте тест на попытку сохранения после ошибки разбора.

Критерий: повреждённый файл сохраняет исходные байты, ошибка доступна UI.
