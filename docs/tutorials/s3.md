# S3

S3 stores objects under a bucket and a key. A key is a string, not a chain of
directories. `photos/2024/hut.jpg` is one object. The slash is a character in
the name. FFM pretends otherwise only while listing: it asks S3 for one
level, using `/` as the delimiter.

## Keys, folders, and files

`list_objects` calls `ListObjectsV2` with delimiter `/`.

- A common prefix becomes a folder row. The name is the prefix with the
  current prefix removed and a trailing `/` stripped. An empty name is dropped.
- Each object becomes a file row, except the object whose key is exactly the
  current prefix (the folder marker).
- The file name is the key with the current prefix removed.
- Folder rows have size 0 and no modification time. File rows keep the object
  size and the last-modified instant, when the stamp is after the Unix epoch.

The call does not follow a continuation token. S3 returns at most 1000 keys
and prefixes for that request. A larger page is truncated, and FFM does not
ask for the rest.

There is no recursive delete. Deleting the folder row's name does not remove
the objects under that prefix, because those objects are separate keys and
the delete call removes one key.

## Path syntax

`VirtualPath::parse` accepts two forms. Anything that does not start with
`s3://` is a local path, including a normal absolute path.

| Text | Profile | Bucket | Prefix |
|---|---|---|---|
| `s3://album/photos/hut.jpg` | `default` | `album` | `photos/hut.jpg` |
| `s3://photos@album/photos/hut.jpg` | `photos` | `album` | `photos/hut.jpg` |
| `s3://album` | `default` | `album` | empty |

The prefix is everything after the first `/`. It is not limited to one
segment. Display prints `s3://profile@bucket` and appends `/prefix` when the
prefix is not empty. A location with no bucket prints `s3://profile@`.

This type is the library's parse of a string. Panel paths are still local
`PathBuf` values. Parsing `s3://...` does not point a panel at a bucket.

## Operations in the library

`S3Client::new(profile)` builds a blocking Tokio runtime and the client from
[the AWS profile rules](aws.md). The methods are:

| Method | AWS call | Limit |
|---|---|---|
| `list_buckets` | `ListBuckets` | The buckets in that one response |
| `list_objects` | `ListObjectsV2` with delimiter `/` | One page, one level |
| `download_object` | `GetObject` | The whole body is collected in memory, written to a temporary file in the destination directory, then renamed onto the destination path |
| `upload_object` | `PutObject` | The whole local file is read into memory |
| `delete_object` | `DeleteObject` | One key |
| `copy_object` | `CopyObject` | Source is sent as `bucket/key`. There is no separate move |

Copy stays inside S3. It does not download. A key that contains characters
S3 expects to be encoded in the copy source can fail, because the client
sends the bucket and key as written.

The panels do not call these methods. `Alt+F1` / `Alt+F2` on an `S3: name`
row sets the status text `S3 profile 'name' selected (S3 browser coming soon)`
and leaves the directory unchanged.

## MCP tools

The `ffm-mcp` process exposes the same account to an agent. Local paths in
upload and download are confined to the server root (`FFM_MCP_ROOT`, or the
process working directory). Bucket names and keys are not local paths, so
that root check does not apply to them.

| Tool | Arguments | Result |
|---|---|---|
| `s3_list_profiles` | none | Section names from the credentials file |
| `s3_list_buckets` | `profile` | Bucket name and creation date |
| `s3_list_objects` | `profile`, `bucket`, optional `prefix` | One level of folder and file rows |
| `s3_download` | `profile`, `bucket`, `key`, `local_path` | Writes that path under the MCP root. An existing file is replaced |
| `s3_upload` | `profile`, `bucket`, `key`, `local_path` | Reads a file under the MCP root and puts it at that key |
| `s3_delete` | `profile`, `bucket`, `key` | Deletes that one key |
| `s3_copy` | `profile`, `source_bucket`, `source_key`, `dest_bucket`, `dest_key` | Copies inside S3 |

`list_drives` on the same server includes the profile names next to the local
drives. It does not open a bucket either.

Build the TUI with the feature when you want the drive-menu rows:

```bash
cargo build --features s3
```

The MCP package already depends on the S3 SDK. Rebuild `ffm-mcp` after
changing it. Do not expect either binary to create buckets, change ACLs, or
walk every key in a large prefix. Those calls are not implemented.
