# FunnyFileManager — Development Roadmap

_Generated 2026-07-26 from a multi-agent subsystem survey (far-parity, core-ux, code-health, testing-ci, integrations) with adversarial synthesis. A point-in-time snapshot; the tree is actively developed._

## Executive summary

FFM's core architecture is genuinely healthy (clean ops/handlers split, self-enforcing structural tests, no unwrap/panic in prod, tuned clippy). The real work clusters in six areas. The most urgent items are cheap and high-leverage: one documented-but-broken feature (Backspace parent nav), two CI/tooling gaps that actively mislead the autonomous agents developing this repo (S3 unit suite never runs in CI; /test slash command points at retired tarpaulin tooling), and a live MCP bug reachable by any connected AI agent today (S3 listing silently truncates above 1000 keys). Beyond those, the biggest user-facing holes are the total lack of cross-run persistence (bookmarks/sort/paths reset every launch), synchronous copy/move that freezes the whole TUI with no progress or cancel, and two mature-but-unwired backends (S3Client and keepass.rs are fully tested libraries with zero UI callers). A recurring theme is documentation drift: CLAUDE.md's hotkey table and Module Reference, the F1 help overlay, and the S3 knowledge-base doc all contradict the actual code — dangerous because the knowledge base is the stated single source of truth for autonomous agents. The plan front-loads P0 quick wins and the two independent-but-foundational items (persistence infra, S3 pagination), then sequences the two big rocks (async copy/move; S3 panel wiring) behind their prerequisites.

## Sequencing notes

Two P0s are literally one-line/doc changes with local verification already done (S3 --lib, /test skill) — do them first, they de-risk everything the autonomous agents touch afterward. The Backspace fix is the third trivial P0 (a branch inside an existing match arm).

Big-rock warnings and ordering constraints:
(1) S3 pagination fix MUST land before S3 panel wiring — otherwise the new browser ships the truncation bug. Wiring is XL and needs an explicit go/descope decision at planning time; do the cheap S3 KB doc correction first so expectations are honest regardless of the outcome.
(2) Async copy/move (XL) and the F5/F6 editable-destination dialog (L) both rewrite the same transfer call sites (src/ops/file.rs:261-310). Sequence async copy/move FIRST (or design them together) to avoid reworking the dialog against a changed execution path. Both are big — don't schedule them in the same sprint as the S3 wiring rock.
(3) The persistence task establishes the config-file seam that hidden-file toggle, filter, and aliases can all reuse — land it early; aliases explicitly depend on it. Guard the App::new()-never-touches-disk invariant.
(4) The mcp/ crate has three overlapping tasks — split main.rs, add S3 tool tests, make AWS optional. Do the split first (it moves the code the other two touch), then tests, then feature-gating; all three interact with the tool_names parity test.
(5) Windows CI (merged from two surveys) and cargo-audit are independent P1 CI adds that can go in any sprint; expect the first Windows run to go red and budget for it.
(6) The three documentation tasks (hotkey/S3 correction, Module Reference backfill + drift test, F1 help) are cheap, independent, and each includes a guard against re-drift — batch them into a single low-risk doc sprint; this repo's agents actively read these docs as source of truth, so their payoff is disproportionate to effort.
